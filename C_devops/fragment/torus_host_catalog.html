Product push rule (fsdevopstracker)

Hostpark product paths (e.g. opry/devops/ti_punch/…) are usually published via fsdevopstracker hostpark-push <rel> goal=<why>, not only identity _publish.mjs. Every write that changes tip or hostpark bytes needs a real why-string. Goals ledger: {project}/devops/goals.json. Ops lineage: {project}:devops:ops. See flow-model devops-goals and fsdevopstracker readme. This catalog lists routes; goals explain each generation.

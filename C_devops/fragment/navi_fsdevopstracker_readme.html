fsdevopstracker

Native navi module for flow-model devops — index a project directory into tip+bin space, track goals/sprints, CRUD artifacts with provenance, mirror logical routes for relay test, and hostpark-push shipped bytes. Not a flow-model product itself. Indexes artifact_type including assets (static art under assets/ — not ui screen roles).

v0.9.0 concurrent projects: every project-scoped op requires project=<name> (POST JSON or path kv). Shared active_project is not used for ops — safe to relay two projects on one nest. use <name> only sets an in-memory REPL session default. hostpush all means all tips in that project only.

Mod park: torus testkit mod fsdevopstracker — mount torus testkit mod fsdevopstracker in navi>. Relay: …/navi-jumbo/fsdevopstracker/…

Three layers of addressing

LayerShapePurpose
Devops tips {project}:{rel/path} Working set — get, put, append, ops, disk-push
Route prefix opry/devops/ti_punch (from project config.json flowerpot.root) Logical product path for artifacts
Mirror (local) navi/{route_prefix}/{rel} Relay GET test — …/navi-jumbo/{route_prefix}/{rel}
Hostpark (remote) {route_prefix}/{rel} on hostpark Deployment — hostpark-push

Commands

Index and devops

  • fsdevopstracker start — fsdevops> REPL
  • init / reinit / use / list / get / link
  • put|append goal= required — real why (not “refresh tip from disk”); POST JSON body via relay for large text. Normative: devops-goals
  • goals / sprint / pending — goals ledger (devops/goals.json); distinct from per-op goal= strings on ops
  • ops-reset — import bulk devops/ops.json as ops-batch on {project}:devops:ops
  • ops [n] — recent ops from lineage tip
  • disk-push — tips to project root on disk

Routes and mirror

  • route — show route_prefix
  • mirror — rebuild navi/{route_prefix}/… parks from existing devops tip bins (does not reread disk — put first after edits)

Hostpark push

  • push — hostpark config (policy, key, token stash)
  • token stash path=… / token feed / token load
  • keychain — mount signing mod
  • hostpark-push <rel> goal= — PUT tip bin to hostpark at {route_prefix}/{rel}; same goal= quality rule as put

Goals standard (short)

  • Every content write: goal=<why> — intent / product reason; layer or variant prefix when helpful
  • Goals ledger (devops/goals.json) = planned work; ops ledger (:devops:ops) = what shipped with that why
  • List new hostpark routes on torus/host-catalog; goals explain generations, they do not replace the catalog

One-time setup (per project)

fsdevopstracker use ti_punch
push policy=<addr^gib>
token load <project>/credentials/hostpark_tokens_minted.json
keychain

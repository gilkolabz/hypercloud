scripts/ua_get — shared User-Agent park handler

Foobarch hostpark pattern: one write-gated Lua script tip, many consumer parks that carry their own menu in frame data.

What is parked where

ib role
scripts/ua_get Shared Lua bin (text/x-lua). Classifies the request, reads this consumer park’s menu from req.tip.data, serves the chosen bin. Gated and write-protected under policies/foobarch-shell.
readme/scripts/ua_get This HTMF readme. Same gate + write-gate policy.
your/park Your content tip. Point http.GET at the Lua script; put the per-park menu in data.ua (or http.GET.ua).

How GET resolves

  1. Request hits a consumer park (e.g. testkit/text_editor).
  2. That tip’s http.GET is { "kind": "lua", "script": "scripts/ua_get" } (live tip ib or pinned ib^gib).
  3. Host loads the Lua from scripts/ua_get and calls handle(req).
  4. req.tip is the consumer frame (ib, addr, data, rel8ns) — not the script tip.
  5. Lua reads req.headers (lower-cased), classifies User-Agent, picks a case from data.ua.cases, serves the matching bin.
  6. Accept: application/eframe alone skips Lua entirely and returns the consumer frame JSON (Content-Type: application/eframe). Legacy application/ibgib+json still maps to eframe.

Consumer frame shape

Minimal browser + CLI split using extra rel8ns slots:

{
  "ib": "testkit/text_editor",
  "gib": "…",
  "data": {
    "parts": ["network_proposal", "ibgib_frame", "manifest", "json"],
    "park": "defer",
    "gate": true,
    "content_type": "text/html; charset=utf-8",
    "default_method": "GET",
    "http": {
      "GET": { "kind": "lua", "script": "scripts/ua_get" },
      "PUT": { "kind": "commit" }
    },
    "ua": {
      "default": "default",
      "cases": {
        "default": { "kind": "bin" },
        "chrome":  { "kind": "bin" },
        "firefox": { "kind": "bin" },
        "safari":  { "kind": "bin" },
        "edge":    { "kind": "bin" },
        "cli":     { "kind": "bin", "rel8n": "ua_cli" },
        "curl":    { "kind": "bin", "rel8n": "ua_cli" }
      }
    },
    "n": 1
  },
  "rel8ns": {
    "bin": ["bin <html sha>"],
    "ua_cli": ["bin <plaintext sha>"],
    "policy": ["policies/torus^…"],
    "past": ["…"]
  }
}

Where each case gets its bytes

case action bin used
{ "kind": "bin" } rel8ns.bin[0] on the consumer tip (default HTML)
{ "kind": "bin", "rel8n": "ua_cli" } rel8ns.ua_cli[0]
{ "kind": "bin", "rel8n": "ua_edge" } rel8ns.ua_edge[0] — any named slot you add
{ "kind": "bin", "bin": "abc…" } explicit sha in the case (no rel8n key)
{ "kind": "body", "body": "…" } inline UTF-8 body
{ "kind": "park_request", "path": "/other/park" } internal re-dispatch to another hostpark

Case names alone do not pick different bins. You must set rel8n, bin, body, or path on each case that should differ.

data.ua fields

field meaning
default Case id when nothing matches (usually "default")
cases Map of case id → action table
map Optional rename: detected id → case id
passthru_header Default x-navi-ua-passthru
case_header Default x-navi-ua-case
passthru Case used when passthru header is truthy

Menu may live at data.ua or nested under data.http.GET.ua. Lua checks data.ua first.

Classifier ids (Lua output)

edge, ie, chrome, firefox, safari, opera, cli, curl, bot, unknown

Edge is checked before Chrome (Edge UA contains Chrome/Safari tokens). cli covers navi_shell, undici, node-fetch, wget, etc.

Request header overrides

header effect
X-Navi-Ua-Passthru: 1 Skip classify; use ua.passthru or ua.default
X-Navi-Ua-Case: cli Force that case id (unknown → default)

Response headers include X-Navi-Ua-Detected, X-Navi-Ua-Case, X-Navi-Ua-Script.

Fail-open behavior

  • Missing data.ua → serve rel8ns.bin
  • Unknown case → ua.default, then rel8ns.bin
  • Missing bin sha → 404 text, not a Lua crash

Write protection

  • scripts/ua_get and consumer tips link rel8ns.policy to their identity policy (policies/foobarch-shell, policies/torus, …).
  • Mut8 requires signed commit (proposal-write-v1) + usage token.
  • data.gate: true wins delimiter races on that ib (bypass: X-Navi-Gate-Passthru: 1).

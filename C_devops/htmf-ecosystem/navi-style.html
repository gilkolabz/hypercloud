Navi devops style

Devops style for the foobarch/navi framework. Products can hide the build pattern entirely from end users.

Production solutions

Expose API via foobarch proposals and/or ship a PWA in a non-root browser shell. JS depth (MPA vs heavy client) is a per-product choice; navi runtime and the foobarch shell pattern are always available.

  • foobarch.net is the dispatch origin. Named routes on that host are hostpark tips.

See navi modules guide for the module contract.

A project

A product is a set of hostpark routes plus the tips a session keeps. Write down three things where people can read them:

  • scope: what the product is for
  • a decisions log: why a shape was chosen
  • the route prefix the product lives under
